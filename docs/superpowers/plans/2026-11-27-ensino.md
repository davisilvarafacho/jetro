# Módulo de ensino Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cursos, inscrições, aulas (com professor e data) e presença, com a presença modelada para escala.

**Architecture:** Quatro tabelas novas em Prisma/SQLite. `LessonAttendance` tem chave composta `(lessonId, memberId)` e grava só quem veio. Inscritos e presentes são listas paginadas na tela, então o formulário envia só o delta (`add`/`remove`), como `GroupMembersField` já faz. Telas `/cursos` e `/aulas` clonam o padrão de `/ministerios`.

**Tech Stack:** Next 16 (App Router, server actions), Prisma 7 + better-sqlite3, Mantine 9, zod, `node:test` via `tsx` (sem dependência nova).

**Spec:** `docs/superpowers/specs/2026-11-27-ensino-design.md`

## Global Constraints

- Trabalhar direto na `main`, sem worktree; um commit por tarefa, sem push.
- **Árvore suja:** há trabalho antigo não commitado em `prisma/schema.prisma`, `package.json`, `src/lib/members.ts`, `src/app/(app)/membros/actions.ts`, `src/app/(app)/membros/delete-member.tsx` e `scripts/seed.ts` (sem rastreio). Cada commit usa `git add` com caminhos explícitos. Para arquivos já sujos, **antes da Tarefa 1** o usuário commita o trabalho antigo; sem isso, o commit do ensino levaria a remoção do líder junto.
- `AGENTS.md`: este Next tem mudanças incompatíveis. Antes de escrever página ou server action nova, ler o guia correspondente em `node_modules/next/dist/docs/01-app/` e copiar o padrão dos arquivos de `ministerios/`.
- Identificadores em inglês (`Course`, `Lesson`, `LessonAttendance`, `CourseEnrollment`); rotas, rótulos e mensagens em português (`/cursos`, `/aulas`).
- Presença: `@@id([lessonId, memberId])`, `@@index([memberId])`, sem `id` e sem FK para a inscrição. Falta = ausência de linha.
- Cascade: curso → aulas, inscrições; aula → presenças; membro → inscrições e presenças. `Lesson.teacherId` é `Restrict`.
- Datas de aula são "só dia": `DateTime` guardado como meia-noite UTC, trafegado como string `YYYY-MM-DD`, exibido `DD/MM/AAAA` sem passar por fuso.
- Páginas de 25 (`PAGE_SIZE`), cursor por chave ordenada, `take: PAGE_SIZE + 1` para saber `hasMore`.
- Testes de dados: `pnpm test` (banco `test.db` descartável). Telas e server actions não têm harness: verificar com `pnpm exec tsc --noEmit`, `pnpm lint` e o navegador.

## Review Focus

- Chamada com ids repetidos, de membro que não existe ou já presente: ignora, não quebra (Tarefa 2).
- Salvar com `memberChanges` vazio, ausente ou JSON inválido: não apaga ninguém (Tarefa 2).
- Data inválida (`2026-02-30`, vazia) é rejeitada, e uma aula em `2026-03-01` aparece como `01/03/2026` em qualquer fuso (Tarefas 2 e 7).
- Lista com exatamente 25 e com 26 itens: `hasMore` correto e cursor não repete nem pula (Tarefa 3).
- Excluir professor de aula é bloqueado com mensagem; membro só com presença ou inscrição é excluído e as linhas somem (Tarefas 1 e 4).
- Curso com nome repetido dá erro no campo; duas aulas de mesmo nome em cursos diferentes são permitidas (Tarefas 1 e 5).
- CSV: nome com `;`, aspas, acento ou começando em `=`/`+`/`-`/`@` sai escapado e sem virar fórmula; aula sem presença gera só o cabeçalho; aula inexistente dá 404 (Tarefa 8).
