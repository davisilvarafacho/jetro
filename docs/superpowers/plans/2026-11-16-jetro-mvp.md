# JETRO MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App web local (notebook) com login, cadastro de membros (com líder e parça) e cadastro de ministérios, no visual "Pastoral".

**Architecture:** Next.js App Router com Server Components para leitura e Server Actions para escrita. Prisma 7 sobre SQLite local via `@prisma/adapter-better-sqlite3`. Autenticação feita à mão: bcryptjs + JWT (jose) em cookie httpOnly, verificado em `src/proxy.ts`. UI em Mantine com tema derivado de `DESIGN.md`.

**Tech Stack:** pnpm, TypeScript, Next.js 16, React 19, Prisma 7.10 + better-sqlite3, Mantine 9 (`core`, `hooks`, `notifications`), `@tabler/icons-react`, zod 4, jose 6, bcryptjs 3, tsx.

**Spec:** `docs/superpowers/specs/2026-11-16-jetro-mvp-design.md` + `DESIGN.md` (visual) + `prototipo-3-pastoral.html` (referência visual navegável).

## Global Constraints

- Sem testes automatizados (decisão do usuário). Verificação de cada task = `pnpm exec tsc --noEmit`, `pnpm lint` e o roteiro manual da task no navegador.
- Toda a UI em pt-BR. Mensagens sobre pessoas usam frase neutra pelo nome, nunca "ele/ela".
- Obrigatórios: CPF, nome e sobrenome do membro; nome e líder do ministério; nome, email e senha do usuário. Líder e parça do membro são opcionais.
- CPF armazenado só com 11 dígitos; exibido como `000.000.000-00` com `tabular-nums`.
- Coral (`#C9472A` / fundo `#FDEBE4`) é exclusivo para "sem líder". Vermelho (`#C42D3A`) é exclusivo para erro/excluir.
- Tokens visuais vêm de `DESIGN.md`; em dúvida de aparência, abrir `prototipo-3-pastoral.html` e copiar.
- Primeiro commit do repositório: mensagem exatamente `Versionamento do projeto` (sem trailer). Demais commits: mensagem curta em pt-BR + linha `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Não usar a barra "Telas" do protótipo no produto.

## Review Focus

1. CPF colado com máscara (`529.982.247-25`) ou com dígitos repetidos (`111.111.111-11`): o primeiro é aceito e salvo como `52998224725`; o segundo é "CPF inválido". → Task 3, roteiro manual.
2. Editar um membro sem mudar o CPF: não pode acusar "Este CPF já está cadastrado" (a checagem de unicidade exclui o próprio id). → Task 4, roteiro manual.
3. Ciclo indireto de liderança (A lidera B, B lidera C; tentar pôr C como líder de A) é recusado. → Task 4, roteiro manual.
4. Email com maiúsculas/espaços (`  Admin@Igreja.org `) no `create-user` e no login: normalizado com `trim().toLowerCase()` nos dois lados, então loga. → Tasks 2 e 3.
5. Cookie de sessão adulterado ou expirado: redireciona para `/login` sem erro 500. → Task 3, roteiro manual.
